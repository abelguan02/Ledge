# 新应用产品简报

日期：2026-10-28。应用名英文 **Ledge**、中文 **搁这儿**〔用户确认 2026-10-31〕，取代原名 Dump〔用户确认 2026-10-28，已改〕；文件夹保留 `HUDWorkbench`。bundle ID 与数据目录随之改为 `local.ledge.desktop`、`Ledge`〔用户确认 2026-10-31〕；Codex 实施前代码仍是 Dump（见第 9 节第 1 项）。

来源说明：标〔用户确认〕的条目来自用户 2026-10-28 在对话中的原话或明确选择；标〔建议〕的是设计方提出、尚待用户确认的做法；标〔待定〕的是还没讨论清楚的问题。本项目基于前期桌面暂存工具的经验重新设计。

## 0. 定位修正（2026-10-28）

用户原话要点〔用户确认〕：

- 不要做成“管理进度的文件夹应用”。它是一个**缓存暂存区**：哪怕存的是副本，也可以放心地直接清空。
- 做任务时，它像一张工作台，什么东西都往里丢。更准确地说，是开始一个项目之前的**头脑风暴区／材料收集区**：看中的参考素材、原型等，**任何格式**都能放进来，包括链接、视频。
- 之后针对不同格式逐步开发对应功能，例如图片处理、视频处理、链接归纳整理（或链接直接显示小预览）。

本节取代下文中“以‘这件事’为中心、记住进度”的说法；“每件事背后是一个真实文件夹”的想法不采用。下文第 2、3、5 节已按此调整。

## 1. 一句话

一个贴在屏幕边缘的材料暂存区：做事或开新项目前，看中的东西什么格式都往里丢；需要时就地处理，用完可以放心清空。

〔用户确认 2026-10-29〕后续开发围绕“素材收集和交接”：素材交给外部专门工具处理，避免增加应用内网页读取、总结等功能。第四阶段先补齐通用拖出／复制格式、批量复制文字与网址、保留来源已提供的标题和网址；保存文件不得退化。不做材料清单、使用要求输入框或应用专用入口。下文链接归纳、联网预览和清单等旧建议不再作为本期路线，以本段为准。现有处理功能本期不移除。

〔用户确认 2026-10-30〕上一条中“不做联网预览”改为：链接卡显示真实网页首屏截图、标题和网站名，收进来时自动生成（带一次性参数的链接除外），同意 Dump 为此联网；所有材料按空格用系统预览面板查看，双击用默认应用打开，去掉 Dump 内的播放器。网页正文读取、归纳和内容提取仍不做。细则见概念稿说明 9.17。

〔用户确认 2026-10-30，真实验收后〕无截图网址的空格预览统一显示本地标题、网站名及完整网址说明，避免系统预览原链接时自行访问；有截图仍预览截图，双击仍打开原网址。第五阶段已实现并完成确认范围验收，当前能力边界见 [README](../README.md)。

## 2. 核心概念

- **收集区**：放材料的地方。〔用户确认 2026-10-28〕收集区可以有多个，但**一个面板永远只显示一个收集区**，不在同一面板上并列多个区。展开的面板要永远干干净净、清清爽爽，像一张空白画布，画布上能放任何格式。不做进度管理。
  - 〔建议〕面板上除了材料本身，只留最少的东西：收集区名字（小字，点它切换）和“清空”。不放统计行、分区标题、提示文字；空的时候就是一片空白。
  - 〔用户确认 2026-10-28〕希望更像真正的头脑风暴画布：材料可以自由摆放，把相关的素材凑在一起。用户担心开发量，因此分阶段做：
    - 〔用户确认 2026-10-28〕第一阶段：画布宽度等于面板宽度，高度可以往下延伸（只能纵向滚动，不能缩放）；材料可以拖到任意位置，松手时轻轻吸附到隐形网格；新放进来的材料自动落在空位，当前区域放不下时画布往下延伸，所以永远不会“放不下”；位置会被记住。可以切换和新建收集区。细则见概念稿说明 9.7–9.9。
    - 〔建议〕第二阶段：画布可以二维平移和缩放；面板可以临时“铺开”成更大的画布。
    - 〔建议〕第三阶段：调整卡片大小、框选多个材料一起移动、把几张叠成一摞。
    - 每个阶段都能单独使用，做不完后面的也不影响前面的。
  - 〔用户确认 2026-10-28〕切换收集区属于第一阶段：点面板顶栏的收集区名字，弹出菜单切换、新建、改名、删除；暂不在细线上切换（概念稿说明 9.7）。
  - 〔用户确认 2026-10-31〕菜单增加“管理收集区…”，支持多选、批量删除、分组先导出和整批撤销；确认页在同一弹出层内翻页，右键单区删除共用此页，点击删除时重新统计，允许同名收集区。以概念稿 9.18 为准；已实现并完成主流程验收，见收集区管理开工说明第 6 节。
- **材料**：任何格式都能放进来：文件、图片、文字、链接、视频、音频、文档等。〔用户确认 2026-10-28〕整个文件夹也要接收，作为一份材料复制。只保存副本，原件不动。能放进来不代表已经能处理该格式。
- **清空**：〔用户确认〕可以放心清空整个收集区（或其中一部分）。〔用户确认 2026-10-28〕但“都是副本”只对有外部原件的导入文件成立：粘贴的文字、没有源文件的拖入内容、链接、处理生成的结果，以及原件已被移动或删除的导入文件，都只存在于这里。清空确认框要按实际内容说明有几样会彻底消失，并提供“先导出”和清空后的一次“撤销”。细则见概念稿说明 9.10。
- **动作**：对选中材料做的处理，比如翻译、压缩、识别文字。工具以“动作”的形式出现，而不是独立面板。〔用户确认：选择 C 方向“一个工作台，而不是六个面板”〕
- **结果**：动作产生的新材料，放在原件旁边并记住来自哪个原件。〔用户确认 2026-10-28〕不做“待取”之类的进度标记；它属于“只存在于这里”的内容，清空时会被单独提示。

## 3. 界面结构

### 3.1 细线（收起时）

- 不分五段，也不按工具分段。〔用户确认〕
- 只表达收集区的状态，要简单。〔用户确认〕
- 〔建议〕只分三种：平静（没事）、在动（有东西在处理）、亮起（处理完成、需要你看一眼；出错时变红）。材料数量不放在细线上。

### 3.2 投放面板（拖东西靠近时）

- 只做投放这一件事，界面干净。〔用户确认〕
- 投放内容可以按工具或材料类型细分。〔用户确认〕
- 〔建议〕根据拖动的东西现场生成格子：中间最大的一格永远是“放进来”，只收进来，不做处理；旁边最多两三个小格，是适合这类材料的直接动作（拖图片时显示“压缩”“识别文字”，拖文字时显示“翻译”“解释”）。松手就执行。
- 〔建议〕面板上没有说明文字，也没有灯光，只有格子和格子里的词。

### 3.2a 文字入口

- 文字主要靠复制粘贴进入，不靠拖拽：复制之后打开面板就能直接粘贴。〔用户确认 2026-10-28〕
- 〔用户确认 2026-10-28〕面板上**不放常驻输入框**（保持空白画布）。面板打开时按 ⌘V，剪贴板文字直接变成画布上的一张便签，上方浮出动作胶囊；只在按 ⌘V 时读取剪贴板。具体见概念稿说明 9.4。

### 3.3 工作台（展开时）

以概念稿说明第 9 节为准，要点：

- 〔建议〕顶栏只有收集区名字（点击切换，手动，不做“智能”推断）、“清空”和收起按钮。
- 〔建议〕材料以“物件”的样子自由摆放在画布上，任何格式都有对应样子（链接显示标题和预览，视频显示封面和时长）。
- 〔建议〕选中材料后，底部浮出适用的动作；可以同时选多个同类材料。
- 〔建议〕处理结果作为新材料放在原件旁边；处理进行中时，进度显示在原件上。
- 〔建议〕文字处理的回答是浮在原便签旁的卡片，可以切换动作、继续追问；需要保留就“放到画布上”。

## 3.3a 停靠方式

〔用户确认 2026-10-28〕面板不是一个单独浮起的窗口，而是从屏幕侧边长出来的。以后可以选择停靠在屏幕左侧、右侧或上方。〔建议〕默认右侧；三种位置的样子见概念稿说明第 9.1 节。

## 3.4 视觉方向

〔用户确认 2026-10-28〕选定“原生玻璃”方向（概念稿说明第 5 节；按新定位重画的定稿方向见第 9 节）。其他方向（深色平面、科幻 HUD、Claude 感）不采用，画板保留作参考。

## 4. 颜色

- 面板上不再出现光团或常亮柔光。〔用户确认〕
- 颜色保留两个作用：指示灯，以及区分类别。〔用户确认〕指示灯可以放在角落。〔用户确认〕
- 〔用户确认 2026-10-28〕面板、卡片、背景全部用中性色，没有光晕，也没有大面积色块。定稿方向里材料类型靠各自的样子区分（照片、便签、链接卡、文档图标），不再加彩色小圆点；应用自身的颜色只剩细线这盏指示灯。选中时使用系统强调色蓝色〔用户确认 2026-10-28〕。

## 5. 按格式逐步增加的能力

〔用户确认〕先做到“任何格式都能放、能看、能拖出去”，再针对格式逐步加处理功能。

| 格式 | 放进来后能看到 | 处理功能（逐步开发） | 阶段 |
| --- | --- | --- | --- |
| 任何文件 | 图标、名字、大小 | 拖出去（默认复制）、查看来源、清空 | 首版 |
| 文字 | 前几行内容 | 翻译、解释、总结、润色、改写（复用 Ming，经 Codex） | 首版 |
| 图片 | 缩略图 | 压缩、调整尺寸、转格式、识别文字（复用 Ming） | 首版 |
| 链接 | 〔用户确认 2026-10-30〕网页首屏截图、标题、网站名（概念稿说明 9.17） | 不做网页正文读取、归纳和内容提取；按空格看截图，双击用浏览器打开 | 第五阶段 |
| 视频 | 〔建议〕封面帧、时长 | 〔建议〕压缩、转格式、截取片段、提取音频、转文字 | 后续 |
| 音频 | 时长 | 〔建议〕转格式（如 M4A → MP3）、转文字 | 后续 |

〔待验证〕链接预览需要访问对应网站读取标题和预览图，这会产生网络请求；链接归纳需要应用自己抓取网页正文再交给 Codex（Codex 一侧的联网搜索是关闭的）。视频处理在 macOS 上优先用系统自带的 AVFoundation，不够时再评估其他工具。

以后自己开发的小工具，通过声明“能处理哪类材料”接入，自动出现在对应动作里。〔建议〕首版先不做接入机制，但数据结构要留好位置。

## 6. 不在范围

- 进度管理、任务追踪、项目管理。〔用户确认 2026-10-28：不要做成管理进度的文件夹应用〕
- 音量及其他没有材料的控制类工具。〔用户确认：音量和要处理的文件配合不上〕
- 云同步、账号、天气、日历、邮件。
- AI 用量或额度仪表盘。

## 7. 继承自 Ming 的边界

- 只保存副本，原件不动；拖出默认复制；不自动删除任何东西。
- AI 复用本机已登录的 Codex：不复制令牌、不接管原对话、不弹登录、不在主流程加 API Key；工具和 MCP 一律关闭。
- 未发送的输入和手动修改要有保护；收起不等于结束。
- 系统开启“减少动态效果”时，去掉过冲和循环动画。

## 8. 平台与技术

- 先做 macOS 原生：SwiftUI + AppKit。〔用户确认〕
- Windows 仍是目标，以后单独做界面层；核心逻辑与界面分层，不把 macOS 的验证当成 Windows 已支持。〔建议〕
- 复制 Ming 的后台模块后再整理，界面全部重写；Ming 原文件一个都不改。〔用户确认〕可复用清单见复盘第 5 节。
- 新应用使用自己的 bundle ID、数据目录和签名要求，不和 Ming（`local.aihud.desktop`）共用，两者可以同时安装互不影响。〔建议〕
